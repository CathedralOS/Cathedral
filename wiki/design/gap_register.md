**How to use:** check an item off when its mechanism lands (a `### The decided mechanism` section in the chapter, or the hole otherwise closed) and note the commit. The biggest *cross-cutting* unknowns also live in [appendix_open_questions.md](appendix_open_questions.md) (the prose "ripple" view); this register is the granular per-chapter work list.

Recorded in [[data_model_and_privacy]].
- [x] **Minimal trusted broker — pattern decided.** Route tickets, never hold authority (a ticket only redeems in the target's arena); shrink the trusted part to the one routing invariant, push processing to untrusted endpoints, seal payloads (sealer/unsealer), don't trust the driver, lean on hardware steering. - [x] **Borrow vs. hot-swap — safety resolved; liveness is policy.**
  Reclamation waits while an old-era borrow or loan can still address its
  lifetime cohort. Ordinary short borrows often drain at lexical/graph exits,
  but suspension-safe loans, DMA, foreign retention, callbacks, and parked
  activations may pin an era indefinitely. Before publication the
  replacement plan therefore admits either a real cancellation/revocation
  protocol or explicit coexistence with provisioned retention cost. Safety is
  never purchased by assuming a bounded drain.

Local-first is the zero default (aggregates leave, raw stays on-device); **revocable + still-updatable** (updates = fetch+verify+hot-swap, need no vendor observation; the update-safety floor is a FLEET aggregate not an individual requirement → NOT coercive); DP = opt-in for re-identification-sensitive exports only. **Crash reports/core dumps are a SEPARATE, HARDER problem — flagged OPEN, NOT solved (retracted the "typed-projection proven-secret-free" wishcast):** a core dump is a raw runtime memory snapshot bypassing the type system, so `Secret<T>` doesn't make it safe (a decrypted secret is plaintext in a buffer at crash time). Grounded prior art: known secrets → **no-dump memory region** (`MADV_DONTDUMP`/mlock/enclave); incidental sensitive data in a raw dump → **real residual**; mitigations = structured-not-raw capture (Crashpad/minidump) + local-first. **`reproduce-don't-dump` is a NATIVE-Omega benefit, not general** — replay = **Cathedral + Omega** (Omega guarantees deterministic-given-declared-effects → app is *constrained* not *cooperating*; Cathedral records/re-serves the effect providers); **foreign/walled code loses the guarantee** (internal thread races, raw rdtsc → clean replay not guaranteed, needs rr-style heavyweight capture), and foreign code is exactly where crashes-with-secrets are most likely → the crash-dump-secret residual is **concentrated in foreign code**. Needs real prior-art review (Crashpad scrubbing, no-dump regions, zeroize/secrecy) before a Cathedral answer.
- [x] `store_and_economic_control` — *decided (thin — derives from Matrix host-chain + capabilities)*: **kill AND visibility both follow the host chain** — *X may see/kill Y iff X is in Y's host chain*; a Matrix sees/kills only its children, reaches outside via a request-up-to-host (honor-or-refuse, held cap), root sees/kills the whole tree; "see beyond the Matrix" = cooperative parent disclosure, never forced. **"Kill" = stop instances (supervisor teardown) + revoke their caps (authority graph)** so restart can't restore. **A store kills only what it HOSTS** — Steam-model (store launches app into a store-Matrix → in host chain → can kill it) vs install-source-only (NOT in host chain → can't touch your realm; can only de-list from its own shelf + publish an advisory you choose to act on); no delist-equals-dead, no remote-kill of your sovereign realm, monopoly structurally absent (no mandatory single host-of-everything). **Admission = a cheap mechanical RE-CHECK** (manifest-vs-policy + reach-ceilings + re-verified proof-certs [de-Bruijn cheap, proving was at build] + provenance), one-time at install, **held by the machine owner** (org holds a scoped ceiling over the work realm); store = a provider NOT the mandatory gate → this sovereignty IS the only real "economic" decision (prevents the walled-garden), commercial terms out of scope. **Revocation = capability_lifecycle machinery** (lazy O(1) bump + fail-on-next-use, active teardown for kill). Continuous-reeval = the live reach-ceiling clamping (config change), not re-running the gate; mid-migration clean (atomic migration). **THE ONE NON-DERIVABLE RESIDUAL = trusting the advisory** ("is this app actually evil?") — acting is derived (host-chain kill), *believing* the claim/source is the **first-pin / trust-bootstrap, PARKED** (security bucket). **Meta: the rest of Part 7 governance = host-chain + caps + authority-graph re-applied → thin by design.**
- [x] `governance_and_extension_boundaries` — *decided (thin)*: "what can be replaced" sorts into **three tiers** by *does anything interoperate through you?* **Tier 1 = frozen semantics (the platform ABI):** capability-model semantics, component/Matrix model, IPC primitive, realm/filesystem semantics, package unit (closure+manifest), compositor/seat contract, driver contract, checker admission — singular/stable like the Win32/syscall ABI (the anti-Linux-userland-fragmentation commitment: N competing init/display/package variants until "runs on Linux" means nothing); evolves ONLY by the versioned-interface discipline (additive+migrated, never redefined in place); contract identity = content-hash, components declare targets in manifests → compatibility = ordinary dependency versioning, **"fork detection" DISSOLVED** (nothing to detect — a system serves the declared contracts or doesn't). **Tier 2 = frozen contracts, open implementations** (drivers, compositor impl, net stack, stores — interface fixed, implementation swaps). **Tier 3 = frozen capability BUNDLES, no contract at all** — leaf roles defined purely by held authority (file explorer = enumerate-no-content-read + execute/launch + mint-open-with; shell, login broker, task manager, legibility agent): nothing calls into them, no ABI, swap any binary granted the bundle → identical behavior/safety, blast radius = the bundle — **this is the mechanism that makes no-blessed-apps work** (a role defined by what it HOLDS not what it SERVES is un-blessable + trivially replaceable). Enforcement = the type system (kinds are tier-1 shapes; can't mint a new kind) + the host chain (can't redefine a contract you don't serve; root serves the platform set). **Experimentation valve = your own Matrix** (synthesize any contracts for your children — contained, forks nothing). Consequence: radically customizable without fragmenting — customization in tiers 2–3, identity in tier 1. Governance of tier-1 = whoever ships the OS, constrained by versioning discipline; closed-source moots multi-steward for now.

## Part 8 — Developer
- [x] `developer_experience` — *decided*: stable tooling inputs are the frozen tier-1 contracts—manifest, numbered external schemas and selected codec policies, proof certificates, historical data/conversions, and source state graphs—while compiler internals may churn. Every report is a typed schema-encoded artifact over one fact base; IDE, CI, and LLM agents are lenses over it. Facts and admission gates are opinionated and rechecked; presentation is replaceable. Runnable entry is a conventional interface rather than a binary-kind bit, and a package may contain a reusable core plus thin frontends. Dependencies are exact pinned closures with content deduplication, never ambient namespace search. Additive schema evolution is the default; breaks use explicit version coexistence and bounded deprecation.
- [x] `debugging_and_tracing` — *decided* (see chapter): **debug authority = "become X"** — full `Debug<X>` is write/inject running as X, inheriting all of X's caps, bounded only by X's authority and *not* containable (debugging needs write); defense is governance not sandbox — **attach-time consent gesture enumerating the inherited bundle**, danger legible (= what X holds), `Observe<X::Events>` the attenuated read-only tier. **Fast path = in-process predicate eval** (GDB fast-tracepoint / in-process-agent prior art, UDB ~1000×) — only escalate to debugger on a *true* hit; foreign code lowers the condition to a **portable bytecode VM**, native Omega **inlines** it. **Fleury's "user-level int3" plea = two costs**: cross-process round-trip (OS software, removed by the in-process agent — owns loader) vs the ring transition (hardware, irreducible on stock x86/ARM). **Trap-free runtime breakpoints = runtime in-place patching, NOT pre-baked probes** (de-wishcast: can't pre-reserve every site, BPs set at runtime); compiler supplies *safe-patch metadata* not probes. **ISA-dominated matrix**: ARM64 fixed-width → clean in-place branch patch, trap-free even for foreign code, no kernel entry on the hot path; x86 variable-width → 5-byte-jmp hazard → `int3` (one kernel entry, in-process handled) the honest default, trap-free only via DBI / recompile-and-hot-swap; **custom ISA = user-mode exception vector → literal user-level int3, zero ring transition incl. on a true stop**. **Stop = stop time** (debugger-as-Matrix owns the clock): all-stop default, a pending hot-swap is frozen-requested, resume re-binds/invalidates BPs, host-revokes-the-Matrix is the critical-patch valve. **Live peek (no freeze) = best-effort consistent cut** (Chandy–Lamport over the message graph — well-defined *because* no shared mutable memory; stragglers flagged, never stall). **Debugger-as-Matrix unifies replay (recorded inputs) / time-travel/what-if (modified) / testing (hostile)**; record the bounded nondeterministic *input stream* not all state (deterministic-given-effects); prod = light trace + full-record armed by the grant. **Cross-version BPs** ride the migration's field-correspondence (stable field numbers); restructuring needs a *debug projection*; the versioned debug-info **format is a debugger-author follow-up (study RAD's RDI), not an OS deliverable**. Residual open: on x86, is per-BP recompile-and-hot-swap worth it vs accepting the one `int3` entry on a hot loop. **SAS-debugging tension RESOLVED (see "Native code in the SAS"):** raw byte-patching (int3/trampolines) is FORBIDDEN in the SAS (only checker-verified code is admitted; an unchecked trampoline = universal SAS escape) — so SAS-native trap-free debugging installs **checked instrumentation** (recompile-and-hot-swap or a toolchain-generated checker-verified patch), never raw bytes; because it's checked, the checker confines it to X's refs/caps → `Debug<X>` stays bounded to X, SAS doesn't die. Raw int3/trampolines = **walled-only**. Practical: **debug an app by temporarily walling it** (cheap raw path in the wall, slower walled exec during the session); only the un-wallable **SAS core** pays checker-verified instrumentation per-BP (proof-caching mitigates). This is a real data point in the **MMU→CHERI vs SAS-via-PCC** lean (cheap in-place debugging is free in the walled/CHERI world, worked-for in the SAS).
- [x] `testing_and_simulation` — *decided*: simulability is the existing
  no-ambient-effects property. A synthetic-world Matrix supplies deterministic
  scheduler, clock, storage, network, input, and fault providers. Simulation is
  reproducible guided/randomized testing and emits counterexample traces; it
  never publishes a contract property, no matter how many bounded states it
  searched. Published guarantees come from structural checking or an authored
  proof over the shipping machine. Deliberately bounded theorems remain valid
  because the bound is part of the statement. Cathedral prioritizes small
  inductive certificates that consumers can cheaply recheck; large verified

  admission, and cryptographic proof arguments remain a separate trust/cost
  trade. Banked in Omega `proof_caching.md` and
  `totality_and_bounded_computation.md`.
