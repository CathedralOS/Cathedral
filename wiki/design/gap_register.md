## Load-bearing (blocks other decided work — close these first)

- [x] **Grant arena schema — DEFERRED TO DEV (impl detail, not an open design question).** The *approach* is fully described: an fd-like `{slot, generation}` arena, named-not-searched, lock-free via the generation counter (revoke = atomic bump, redemption = lockless read-compare, race-safe by construction; paged-slab backing for stable addresses; per-principal scoping bounds contention; only slot allocation needs sync, rare/shardable). The exact entry struct + wire-shapes + query surface are an **implementation detail discovered during development**, not design work to scope in advance.
- [x] **Trust-chain roots — RESOLVED.** The three collapse to one anchored chain: hardware root of trust → measured-good boot → **root (the bare machine) = root of *both* authority and identity**. Users are confined-world "Matrices" root mints; each world's identity = its sealed realm + the credential that unseals it. Recorded in [[identity_and_principals]] (decided mechanism). Residual local follow-ups: root-of-authority bootstrap mechanics ([[capability_model]]) and the no-hardware-root fallback ([[boot_and_trust_chain]]).
- [x] **Serialized / transferable capability — DEFERRED TO DEV.** Approach decided (recorded in [[distributed_boundary]]): a CapTP-style **live reference into the home arena** (revocation = the generation bump), attenuation = **membrane**, offline fallback = a content-addressed epoch-stamped token (Tahoe R/W/V lattice); capabilities are remote-native. The **wire protocol + token format + handoff handshake are an implementation detail discovered during development**, not design work to scope in advance. The cross-machine *vision* (redeem-don't-read, petname/key identity, the **Warden**, cookies-as-durable-caps) lives in [network_trust_fabric](../speculation/network_trust_fabric.md).
- [ ] **The "security/trust bucket" — DEFERRED, re-opens post-OS-dev (do not scope further in advance).** first-introduction / **first-pin** (cold-stranger key trust), **recovery-without-a-backdoor** (reset-not-restore shape decided), and **relay-commons economics**. Per design decision (2026-06-23): scoping these further now buys little — they re-open naturally once OS dev exists to ground them, and the hard parts need a security/crypto expert anyway. Provisional exploration preserved for continuity in [network_trust_fabric](../speculation/network_trust_fabric.md) (born-low + provenance-gated cap-ceiling + structural refusal; non-crypto anti-phishing load-bearing; the trust-bootstrap DAG + confine-collapse + build-root-via-Omega-lattice). **NOT committed; not active design work until dev.**
- [x] **Data-class / IFC — DESCOPED off load-bearing.** The privacy *guarantee* is confinement (no channel = no leak) + operation-capabilities (secrets/wallet/login never hold the value), both already core. IFC (propagating `Secret<T>` labels) is the opt-in *fine-grained residual* (holds-data-AND-channel case), a **language-level** feature, deferred/to-explore (incl. a less-verbose-than-classical-IFC scheme). Recorded in [[data_model_and_privacy]].
- [x] **Minimal trusted broker — pattern decided.** Route tickets, never hold authority (a ticket only redeems in the target's arena); shrink the trusted part to the one routing invariant, push processing to untrusted endpoints, seal payloads (sealer/unsealer), don't trust the driver, lean on hardware steering. Recorded as a pattern in [[kernel_architecture]]; per-broker instances (demux, audit-query) follow it.
- [x] **Borrow vs. hot-swap — RESOLVED (composes with decided machinery).** *Safety:* yes, an outstanding borrow **blocks** the swap — swapping under a live borrow leaves a dangling pointer / use-after-free, so the swap waits for the borrow to drop. *Liveness:* bounded by construction — borrows do **not** cross safepoints (the context-switch keystone in [[scheduler_and_resources]]: quiescing happens at compiler-known safepoints, and an ordinary borrow is returned before the next one), so outstanding borrows drain in bounded time and can only *delay* a swap, never block it forever. *The hard case* — a borrow deliberately held across suspension (a long-lived zero-copy view, a DMA-mapped page) — uses the **drain-handshake** (quiesce → revoke/re-point the borrow → resume), the same machinery as online relocation ([[filesystem_as_database]]) and mapped-grant revocation ([[capability_lifecycle]]); the runtime owns the indirection, so the worst case is a bounded cutover delay, never a dangling pointer. No new mechanism.
