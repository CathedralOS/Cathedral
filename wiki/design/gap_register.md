`human_permission_ux`). **UX is largely the existing world-chooser** (fidelity slots + presets + live per-app panel) + invisible-by-default (auto-sandbox + permission gestures) + composable CLI; never expose the nested mediation tree. **BOOT/STRUCTURE RESOLVED (banked in `security_policy_and_sandboxing` "A Matrix is an object owning its world-realm"):** a Matrix IS an object (content = the stock generic mediator by hash, parameterized not rewritten; children = the world's state: **typed boot-manifest config object** + system overlay + hosted app instances + accreted grants); browsing a Matrix = browsing that tree (files-are-folders); boot = mediator reads manifest → spawns resident set → mediates; **creation = instantiate a template closure** (right-click → New World → preset; fresh realm *references* stock system objects by hash — refcount++, zero bytes, divergence only for overridden entries → a new world ≈ one manifest object; ship = the closure (portable world). **STILL PARKED (small):** the exact manifest *schema* (impl detail, discovered at dev); recompile-to-mirror-JIT specifics; whether power-user "Worlds" are first-class from day one; static-vs-dynamic-manifest auditability tradeoff for general Matrices.
- [x] **Data-class / IFC — DESCOPED off load-bearing.** The privacy *guarantee* is confinement (no channel = no leak) + operation-capabilities (secrets/wallet/login never hold the value), both already core. IFC (propagating `Secret<T>` labels) is the opt-in *fine-grained residual* (holds-data-AND-channel case), a **language-level** feature, deferred/to-explore (incl. a less-verbose-than-classical-IFC scheme). Recorded in [[data_model_and_privacy]].
- [x] **Minimal trusted broker — pattern decided.** Route tickets, never hold authority (a ticket only redeems in the target's arena); shrink the trusted part to the one routing invariant, push processing to untrusted endpoints, seal payloads (sealer/unsealer), don't trust the driver, lean on hardware steering. Recorded as a pattern in [[kernel_architecture]]; per-broker instances (demux, audit-query) follow it.
- [x] **Borrow vs. hot-swap — RESOLVED (composes with decided machinery).** *Safety:* yes, an outstanding borrow **blocks** the swap — swapping under a live borrow leaves a dangling pointer / use-after-free, so the swap waits for the borrow to drop. *Liveness:* bounded by construction — borrows do **not** cross safepoints (the context-switch keystone in [[scheduler_and_resources]]: quiescing happens at compiler-known safepoints, and an ordinary borrow is returned before the next one), so outstanding borrows drain in bounded time and can only *delay* a swap, never block it forever. *The hard case* — a borrow deliberately held across suspension (a long-lived zero-copy view, a DMA-mapped page) — uses the **drain-handshake** (quiesce → revoke/re-point the borrow → resume), the same machinery as online relocation ([[filesystem_as_database]]) and mapped-grant revocation ([[capability_lifecycle]]); the runtime owns the indirection, so the worst case is a bounded cutover delay, never a dangling pointer. No new mechanism.

- [x] `power_management` — *decided* (see chapter; informed by an 18-domain cross-industry sweep — avionics/spacecraft/automotive/datacenter/HPC/mobile/intermittent/telecom/medical/RTOS + ISA-telemetry & OS-vs-firmware axes). **Enforced quiescence** is the broadest win — NOT app-proven (that'd be a wishcast for foreign code): enforced by deprivation of means (no clock/wake cap = no syscall to self-schedule) + the OS not dispatching a backgrounded domain (freezes even a busy-looping foreign blob); contained-not-trusted; what's *provable* is an OS theorem ("no clock/wake cap ⟹ never dispatched") over the proved-Omega scheduler/cap core, holds for foreign code. refinements = charge-the-trigger tail-energy (radio/GPS/flash tails outlive the caller) + explicit coprocessor-on proxy (offload is invisible to cycle proxies); "not measurable on commodity HW" sharpened to "not measurable through *sanctioned* interfaces" (firmware withholds per-rail mJ by policy). **Metering = governed confidentiality-sensitive capability** (`Power::Meter`), NOT an ambient number — PLATYPUS/Hertzbleed turn fine-grained energy/freq into key-leak + remote constant-time break; attenuate by coarsening (per-component totals safe, per-op gated); physical PDN-droop channel NOT closeable by caps (needs HW power-domain isolation → sandboxing). **Power envelope, not a ceiling** = {sustained ceiling, rate-limit dP/dt slew-bounded + power-profile declaration, floor (e.g. survival-heater minimum), enclosure/skin-temp cap}; Energy-observe = the attributed-by-proxy model (not a raw read).
- [x] `audit_compliance_provenance` — *decided (thin — a query over the observability graph)*. **PURPOSE = honesty, not paperwork:** (1) the OS tells YOU the truth (what an app actually did / read / sent, what deleted your file — verify-don't-trust, app claims witnessed-or-proven-absent); (2) forensics (hash-chained + anchored → attacker can't `rm` their tracks, breach reconstructable); (3) compliance-as-a-query for regulators = a FREE side effect of (1). It's the **authority+causality graph, NOT a data-change/CDC log** ("A changed X *because* it held cap C via path P, triggered by E", not "row X changed"). **Does NOT grow forever:** structural graph = current-state (bounded by what-exists, not time); event history = rolling-window-full + **compact-with-age** (deferred compaction → summaries → aggregates); only the flagged subset (sensitive-access/grants/deletions/security) retained long-term tamper-evident; behavioral tracing armed-on-demand; retention = a policy knob (personal = modest rolling window, regulated = the small compliance subset for years, throwaway = nothing). **Two mechanisms with real content:** tamper-evidence = hash-chain (local) + **external anchor** (against the sovereign operator — transparency-log/notary they don't control); **secure deletion under replication = crypto-erase the key** (all replicas → unrecoverable ciphertext wherever they live; proof = the key-destruction event; **legal hold = a cap that fences the wipe**). Rest composes: derivable = graph-facts (query/PCC), human = intent/classification-correctness (spec-vs-intent gap, shrinks-not-zero); compliance query = an `Observe`-family cap, host-chain-scoped, **self-audited** (appears in graph), external auditor = scoped time-boxed cap; evidence gradient proven→anchored-witness→human-attested; reproducible builds = pinned-toolchain-closure, bottoms at the bootstrap seed.
- [x] `telemetry_and_feedback` — *decided (DEFLATED — telemetry is not a primitive)*: telemetry = **gather (observability cap) + send (network cap)**, so the OS vendor's collector is just an app holding observe+network caps, revocable/visible in the authority graph — the ONLY content is "the vendor is not exempt from the capability model." Local-first is the zero default (aggregates leave, raw stays on-device); **revocable + still-updatable** (updates = fetch+verify+hot-swap, need no vendor observation; the update-safety floor is a FLEET aggregate not an individual requirement → NOT coercive); DP = opt-in for re-identification-sensitive exports only. **Crash reports/core dumps are a SEPARATE, HARDER problem — flagged OPEN, NOT solved (retracted the "typed-projection proven-secret-free" wishcast):** a core dump is a raw runtime memory snapshot bypassing the type system, so `Secret<T>` doesn't make it safe (a decrypted secret is plaintext in a buffer at crash time). Needs real prior-art review (Crashpad scrubbing, no-dump regions, zeroize/secrecy) before a Cathedral answer.
- [x] `store_and_economic_control` — *decided (thin — derives from Matrix host-chain + capabilities)*: **kill AND visibility both follow the host chain** — *X may see/kill Y iff X is in Y's host chain*; a Matrix sees/kills only its children, reaches outside via a request-up-to-host (honor-or-refuse, held cap), root sees/kills the whole tree; "see beyond the Matrix" = cooperative parent disclosure, never forced. **"Kill" = stop instances (supervisor teardown) + revoke their caps (authority graph)** so restart can't restore. **A store kills only what it HOSTS** — Steam-model (store launches app into a store-Matrix → in host chain → can kill it) vs install-source-only (NOT in host chain → can't touch your realm; can only de-list from its own shelf + publish an advisory you choose to act on); no delist-equals-dead, no remote-kill of your sovereign realm, monopoly structurally absent (no mandatory single host-of-everything). **Admission = a cheap mechanical RE-CHECK** (manifest-vs-policy + effect-ceilings + re-verified proof-certs [de-Bruijn cheap, proving was at build] + provenance), one-time at install, **held by the machine owner** (org holds a scoped ceiling over the work realm); store = a provider NOT the mandatory gate → this sovereignty IS the only real "economic" decision (prevents the walled-garden), commercial terms out of scope. **Revocation = capability_lifecycle machinery** (lazy O(1) bump + fail-on-next-use, active teardown for kill). Continuous-reeval = the live effect-ceiling clamping (config change), not re-running the gate; mid-migration clean (atomic migration). **THE ONE NON-DERIVABLE RESIDUAL = trusting the advisory** ("is this app actually evil?") — acting is derived (host-chain kill), *believing* the claim/source is the **first-pin / trust-bootstrap, PARKED** (security bucket). **Meta: the rest of Part 7 governance = host-chain + caps + authority-graph re-applied → thin by design.**
- [x] `governance_and_extension_boundaries` — *decided (thin)*: "what can be replaced" sorts into **three tiers** by *does anything interoperate through you?* **Tier 1 = frozen semantics (the platform ABI):** capability-model semantics, component/Matrix model, IPC primitive, realm/filesystem semantics, package unit (closure+manifest), compositor/seat contract, driver contract, checker admission — singular/stable like the Win32/syscall ABI (the anti-Linux-userland-fragmentation commitment: N competing init/display/package variants until "runs on Linux" means nothing); evolves ONLY by the versioned-interface discipline (additive+migrated, never redefined in place); contract identity = content-hash, components declare targets in manifests → compatibility = ordinary dependency versioning, **"fork detection" DISSOLVED** (nothing to detect — a system serves the declared contracts or doesn't). **Tier 2 = frozen contracts, open implementations** (drivers, compositor impl, net stack, stores — interface fixed, implementation swaps). **Tier 3 = frozen capability BUNDLES, no contract at all** — leaf roles defined purely by held authority (file explorer = enumerate-no-content-read + execute/launch + mint-open-with; shell, login broker, task manager, legibility agent): nothing calls into them, no ABI, swap any binary granted the bundle → identical behavior/safety, blast radius = the bundle — **this is the mechanism that makes no-blessed-apps work** (a role defined by what it HOLDS not what it SERVES is un-blessable + trivially replaceable). Enforcement = the type system (kinds are tier-1 shapes; can't mint a new kind) + the host chain (can't redefine a contract you don't serve; root serves the platform set). **Experimentation valve = your own Matrix** (synthesize any contracts for your children — contained, forks nothing). Consequence: radically customizable without fragmenting — customization in tiers 2–3, identity in tier 1. Governance of tier-1 = whoever ships the OS, constrained by versioning discipline; closed-source moots multi-steward for now.
