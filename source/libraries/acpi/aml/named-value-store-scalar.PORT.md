# Scalar named Store and destination admission

Status: tested and frozen at the canonical repository path: 504 checked behavior/control pairs and six constant pairs pass; exact current-input verifier and inventory audit pass.

The existing `named_value_store::store_value` direct-object API retains its destination-first admission, source conversion, failure atomicity, and local Buffer exclusions. This extension adds `store_integer(input, length, unit, store, destination, number, size)` for an already-evaluated unsigned scalar without a fabricated source slot or temporary ObjectStore. IntegerSize normalization happens inside this entry. The existing canonical ImplicitResult and private publisher perform the final typed publication; there is no second Value representation or new byte arena.

`admit_destination(input, length, unit, store, destination)` returns failure-first `DestinationResult::Failure(ConversionFailure)` or `Target(ConversionTarget, extent)`. It checks bounded object count/direct ID, fixed destination kind, and complete canonical String/Buffer backing. Integer extent is zero; String/Buffer extent is the admitted existing byte length. An empty Buffer is a valid observed destination: the positive-extent conversion profile rejects the subsequent scalar Store with Bounds. Admission does not resolve references or establish a name binding, writable authority, or future validity. Both public writers call admission on the current store themselves; neither accepts a caller's Target result as evidence.

Scalar conversion composes `integers::normalize`, `implicit_strings::from_integer`, and `conversions::integer_to_buffer`/`mid`. Existing Integer targets receive the normalized number. String targets receive fixed-width 8/16 uppercase hexadecimal characters. Buffer targets retain their positive extent, truncating or zero-padding the normalized little-endian scalar. Each success resets the destination's inactive/unused byte storage exactly as the existing publisher specifies and retains object identity, links, namespace metadata and all other slots. Failure performs no writes. There is no source ID admission for this scalar API, so a one-object/full store needs no extra capacity and unused source/storage metadata cannot affect an Integer target.

The primary relationship remains ACPI 6.6 [implicit result conversion](https://uefi.org/specs/ACPI/6.6/19_ASL_Reference.html#implicit-result-object-conversion) and [Table 19.7](https://uefi.org/specs/ACPI/6.6/19_ASL_Reference.html#data-type-conversion-rules).
